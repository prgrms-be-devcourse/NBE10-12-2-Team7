# 🧠 팀 지식창고 (wiki)

MarketON(dongnemarket) 레포 안의 **LLM 위키**입니다.
기능/버그/이슈 작업을 마칠 때마다 여기에 문서를 쌓고, 나중에 Claude에게 질문해서 빠르게 파악합니다.

> 핵심 철학: **"기억보다 기록을 (Memory fades. Write it down.)"**
> 문서는 사람이 아니라 **LLM이 읽는다**고 전제하고 일관된 형식으로 씁니다.

각 모듈 폴더의 문서(`backend/backend.md` 등)와 역할이 다릅니다. 경계는 [CLAUDE.md §0](CLAUDE.md) 참고 —
한 줄 요약: **모듈 문서 = "지금 어떻게 생겼나"(현재형), `wiki/` = "왜·어떻게 했고 뭐가 안 됐나"(과거형)**.

---

## 폴더 구조

```
wiki/
├── CLAUDE.md      # ⭐ Claude 문서화 규칙 (가장 중요, 먼저 읽기)
├── INDEX.md       # 📇 전체 색인 (자동 생성) — 태그 역색인·상호참조 포함
├── features/      # 기능: FEAT-###-설명.md
├── bugs/          # 버그: BUG-###-증상.md
├── issues/        # 논의/이슈: ISSUE-###-주제.md
├── decisions/     # 기술 결정 기록 — "왜 이걸 골랐나" (ADR 성격)
└── weekly/        # 주간 로그: YYYY-Www.md
```

각 폴더의 `TEMPLATE.md`가 표준 양식입니다. 문서 번호 `###` = **GitHub PR 번호**.

> 📇 **먼저 [INDEX.md](INDEX.md)를 읽으세요.** 150개 문서를 매번 grep하는 대신 색인 한 번으로
> 후보를 좁힐 수 있습니다. 문서를 추가·수정하면 색인도 다시 생성해야 합니다.

## 팀원 사용법 — 작업 끝나면 3분

작업 브랜치에서 Claude Code를 레포 루트에서 열고:

```
방금 머지한 PR #NNN diff 읽고, wiki/CLAUDE.md 규칙대로
features/(또는 bugs/)에 문서 만들어서 커밋해줘.
```

→ Claude가 프론트매터·파일명·섹션을 규칙대로 채워 문서를 생성하고,
   관련 문서 링크(`related`)까지 걸어줍니다.

> 💡 **규칙**: PR 머지 조건에 "wiki 문서 커밋"을 넣으면 문서화가 자동으로 습관이 됩니다.

## 팀장 사용법 — 자연어로 질문

레포 루트에서 Claude Code를 열고:

```
- 관리자 AI 관련 문서 다 요약해줘. status가 done 아닌 것만.
- BUG-207이 왜 생겼고 어떻게 고쳤는지 3줄로.
- 이번 주(W28) 추가된 기능 정리해줘.
- 인증 관련 문서 전부 찾아서 의존 관계 보여줘.
```

전부 마크다운이라 Claude가 grep하고 교차 참조해 답합니다.

---

## 왜 노션이 아니라 이 방식인가

- 노션은 사람이 클릭해 읽기엔 좋지만, LLM이 전체를 훑고 교차 참조하기엔 불리
- 마크다운 + Git이면 코드 PR·이슈 번호와 자연스럽게 연결 (같은 레포라 더 강함)
- 문서 번호 = GitHub PR 번호라서 "204번 PR 문서" 같은 질의가 즉시 가능
- 실패도 기록 → 모델이 좋아지면 재시도 (죽은 문서가 아니라 살아있는 지식)
