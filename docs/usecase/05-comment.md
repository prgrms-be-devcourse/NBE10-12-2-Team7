# Comment 유즈케이스 (UC-016 ~ UC-019) — 담당: 권건우

⚠️ 댓글 작성/조회는 상품 `existsById`만 확인 → 숨김·삭제(soft) 상품에도 동작(테스트 전략 §8 갭). 회원 상태도 재검증하지 않음(갭 N2).

# UC-016. 댓글 작성

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 유즈케이스 ID | UC-016 |
| 유즈케이스명 | 댓글 작성 |
| Actor | 일반회원 (USER) |
| 목적 | 특정 상품에 댓글을 등록한다 |
| 사전 조건 | 인증됨, 상품 존재 |
| 성공 결과 | 댓글 생성 |
| 실패 결과 | 상품 없음/내용 검증 실패 시 거부 |
| 우선순위 | Medium |
| 담당자 | 권건우 |

## 2. 기본 흐름

1. USER가 상품에 댓글 내용을 입력해 요청한다.
2. 시스템이 내용 형식을 검증한다(공백 불가, ≤500자).
3. 상품 존재를 확인한다.
4. 댓글을 저장한다.
5. 결과를 반환한다(201).

## 3. 예외 흐름

| 번호 | 예외 상황 | 시스템 처리 |
| --- | --- | --- |
| E-001 | 내용 공백 | 400 `COMMON_002` (@NotBlank) |
| E-002 | 내용 501자 | 400 `COMMON_002` (@Size 500) |
| E-003 | 상품 없음 | 404 `PRODUCT_NOT_FOUND` |

## 4. 비즈니스 규칙

- 댓글 내용은 필수, 최대 500자.
- 로그인 사용자만 작성 가능(작성자=토큰 memberId).

## 5. 필요한 데이터 후보

| 데이터 | 설명 |
| --- | --- |
| memberId | 작성자 (토큰) |
| productId | 대상 상품 |
| content | 댓글 내용 (1~500자) |

## 6. 변경되는 데이터

| 데이터 | 변경 내용 |
| --- | --- |
| comments | 신규 row insert |

## 7. API 후보

| Method | URL | 설명 |
| --- | --- | --- |
| POST | /api/products/{productId}/comments | 댓글 작성 (인증) |

## 8. 테스트 관점

| 구분 | 테스트 내용 | 연계 |
| --- | --- | --- |
| 성공 | 정상 작성, 500자 경계 허용 | CM-01, CM-05 |
| 실패 | 상품 없음 | CM-02 |
| 실패(엣지) | 내용 공백/501자 | CM-03, CM-04 |

# UC-017. 댓글 목록 조회

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 유즈케이스 ID | UC-017 |
| 유즈케이스명 | 댓글 목록 조회 |
| Actor | 비회원 (Guest) |
| 목적 | 특정 상품의 댓글을 작성순으로 조회한다 |
| 사전 조건 | 상품 존재 |
| 성공 결과 | 미삭제 댓글 목록(작성순) |
| 실패 결과 | 상품 없음 시 거부 |
| 우선순위 | Medium |
| 담당자 | 권건우 |

## 2. 기본 흐름

1. 사용자가 상품의 댓글 목록을 요청한다.
2. 시스템이 상품 존재를 확인한다.
3. 미삭제 댓글을 작성순(createdAt ASC)으로 조회한다.
4. 목록을 반환한다(200).

## 3. 예외 흐름

| 번호 | 예외 상황 | 시스템 처리 |
| --- | --- | --- |
| E-001 | 상품 없음 | 404 `PRODUCT_NOT_FOUND` |
| E-002 | 댓글 없음 | 빈 리스트 |

## 4. 비즈니스 규칙

- 삭제(soft)된 댓글은 목록에서 제외.
- 정렬은 작성순(오래된 것부터).
- 비로그인도 조회 가능.

## 5. 필요한 데이터 후보

| 데이터 | 설명 |
| --- | --- |
| productId | 대상 상품 |

## 6. 변경되는 데이터

| 데이터 | 변경 내용 |
| --- | --- |
| (없음) | 조회 전용 |

## 7. API 후보

| Method | URL | 설명 |
| --- | --- | --- |
| GET | /api/products/{productId}/comments | 댓글 목록 (공개) |

## 8. 테스트 관점

| 구분 | 테스트 내용 | 연계 |
| --- | --- | --- |
| 성공 | 삭제 제외·작성순 | CM-10, CM-40(R) |
| 실패 | 상품 없음 | CM-11 |
| 성공(엣지) | 댓글 없음 빈 리스트 | CM-12 |

# UC-018. 댓글 수정

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 유즈케이스 ID | UC-018 |
| 유즈케이스명 | 댓글 수정 |
| Actor | 작성자 (Owner) |
| 목적 | 작성자가 본인 댓글 내용을 수정한다 |
| 사전 조건 | 인증됨, 본인 댓글, 미삭제 |
| 성공 결과 | 댓글 내용 갱신 |
| 실패 결과 | 없음/삭제/타인/검증 실패 시 거부 |
| 우선순위 | Low |
| 담당자 | 권건우 |

## 2. 기본 흐름

1. Owner가 새 내용을 입력해 수정을 요청한다.
2. 시스템이 내용 형식을 검증한다.
3. 미삭제 댓글을 조회한다.
4. 작성자 일치를 검사한다.
5. 내용을 갱신한다.
6. 결과를 반환한다(200).

## 3. 예외 흐름

| 번호 | 예외 상황 | 시스템 처리 |
| --- | --- | --- |
| E-001 | 내용 공백/501자 | 400 `COMMON_002` |
| E-002 | 댓글 없음 또는 이미 삭제 | 404 `COMMENT_001 COMMENT_NOT_FOUND` |
| E-003 | 타인의 댓글 | 403 `COMMENT_002 COMMENT_OWNER_ONLY` |

## 4. 비즈니스 규칙

- 삭제된 댓글은 조회 단계에서 "없음"으로 취급(`findByIdAndDeletedAtIsNull`).
- 작성자 본인만 수정 가능.

## 5. 필요한 데이터 후보

| 데이터 | 설명 |
| --- | --- |
| memberId | 요청자 |
| commentId | 대상 댓글 |
| content | 새 내용 (1~500자) |

## 6. 변경되는 데이터

| 데이터 | 변경 내용 |
| --- | --- |
| comments.content | 갱신 |

## 7. API 후보

| Method | URL | 설명 |
| --- | --- | --- |
| PATCH | /api/comments/{commentId} | 댓글 수정 (인증·작성자) |

## 8. 테스트 관점

| 구분 | 테스트 내용 | 연계 |
| --- | --- | --- |
| 성공 | 작성자 수정 | CM-20 |
| 실패 | 없음/이미 삭제/타인 | CM-21~CM-23 |
| 실패(엣지) | 내용 공백/501자 | CM-24 |

# UC-019. 댓글 삭제

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 유즈케이스 ID | UC-019 |
| 유즈케이스명 | 댓글 삭제 |
| Actor | 작성자 (Owner) |
| 목적 | 작성자가 본인 댓글을 논리 삭제한다 |
| 사전 조건 | 인증됨, 본인 댓글, 미삭제 |
| 성공 결과 | deletedAt 기록(soft delete) |
| 실패 결과 | 없음/삭제/타인 시 거부 |
| 우선순위 | Low |
| 담당자 | 권건우 |

## 2. 기본 흐름

1. Owner가 commentId로 삭제를 요청한다.
2. 시스템이 미삭제 댓글을 조회한다.
3. 작성자 일치를 검사한다.
4. 댓글을 soft delete 처리한다.
5. 성공 응답을 반환한다.

## 3. 예외 흐름

| 번호 | 예외 상황 | 시스템 처리 |
| --- | --- | --- |
| E-001 | 댓글 없음 또는 이미 삭제 | 404 `COMMENT_NOT_FOUND` |
| E-002 | 타인의 댓글 | 403 `COMMENT_OWNER_ONLY` |

## 4. 비즈니스 규칙

- soft delete(deletedAt 기록). 삭제 후 목록·수정에서 제외.
- 작성자 본인만 삭제 가능(단, 관리자는 UC-034로 별도 삭제 가능).

## 5. 필요한 데이터 후보

| 데이터 | 설명 |
| --- | --- |
| memberId | 요청자 |
| commentId | 대상 |

## 6. 변경되는 데이터

| 데이터 | 변경 내용 |
| --- | --- |
| comments.deletedAt | now() 기록 |

## 7. API 후보

| Method | URL | 설명 |
| --- | --- | --- |
| DELETE | /api/comments/{commentId} | 댓글 삭제 (인증·작성자) |

## 8. 테스트 관점

| 구분 | 테스트 내용 | 연계 |
| --- | --- | --- |
| 성공 | 작성자 삭제 → deletedAt 기록 | CM-30 |
| 실패 | 없음/이미 삭제/타인 | CM-31, CM-32 |
