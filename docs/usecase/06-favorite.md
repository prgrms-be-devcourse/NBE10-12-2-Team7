# UC-020. 관심상품 등록

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 유즈케이스 ID | UC-020 |
| 유즈케이스명 | 관심상품 등록 |
| Actor | 일반회원 (USER) |
| 목적 | 상품을 관심목록에 추가한다 |
| 사전 조건 | 인증됨, 상품 존재, 미등록 |
| 성공 결과 | 관심 등록 생성 |
| 실패 결과 | 상품 없음/중복 등록 시 거부 |
| 우선순위 | Medium |
| 담당자 | 권건우 |

## 2. 기본 흐름

1. USER가 상품을 관심 등록 요청한다.
2. 시스템이 상품 존재를 확인한다.
3. 동일 사용자의 기존 등록 여부를 확인한다.
4. 관심을 저장한다.
5. 결과를 반환한다(201).

## 3. 예외 흐름

| 번호 | 예외 상황 | 시스템 처리 |
| --- | --- | --- |
| E-001 | 상품 없음 | 404 `PRODUCT_NOT_FOUND` |
| E-002 | 이미 관심 등록함 | 409 `FAVORITE_001 FAVORITE_ALREADY_EXISTS` |
| E-003 | 사전체크 통과 후 UNIQUE 위반(race) | 409 `FAVORITE_ALREADY_EXISTS`로 변환 |

## 4. 비즈니스 규칙

- (member_id, product_id) 조합은 유일(DB UNIQUE 제약).
- 동시성으로 인한 중복 insert는 `FAVORITE_ALREADY_EXISTS`로 변환.

## 5. 필요한 데이터 후보

| 데이터 | 설명 |
| --- | --- |
| memberId | 등록자 (토큰) |
| productId | 대상 상품 |

## 6. 변경되는 데이터

| 데이터 | 변경 내용 |
| --- | --- |
| favorites | 신규 row insert |

## 7. API 후보

| Method | URL | 설명 |
| --- | --- | --- |
| POST | /api/products/{productId}/favorites | 관심 등록 (인증) |

## 8. 테스트 관점

| 구분 | 테스트 내용 | 연계 |
| --- | --- | --- |
| 성공 | 정상 등록 | FV-01, FV-05 |
| 실패 | 상품 없음, 중복 | FV-02, FV-03 |
| 실패(동시성) | UNIQUE 위반 변환 | FV-04, FV-33(R) |

# UC-021. 내 관심목록 조회

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 유즈케이스 ID | UC-021 |
| 유즈케이스명 | 내 관심목록 조회 |
| Actor | 일반회원 (USER) |
| 목적 | 본인이 등록한 관심상품을 최근순으로 조회한다 |
| 사전 조건 | 인증됨 |
| 성공 결과 | 관심상품 목록(최근 등록순) |
| 실패 결과 | — |
| 우선순위 | Medium |
| 담당자 | 권건우 |

## 2. 기본 흐름

1. USER가 관심목록을 요청한다.
2. 시스템이 본인 관심을 createdAt DESC, id DESC로 조회한다.
3. 목록을 반환한다(200).

## 3. 예외 흐름

| 번호 | 예외 상황 | 시스템 처리 |
| --- | --- | --- |
| E-001 | 비인증 접근 | 401 |
| E-002 | 관심 없음 | 빈 리스트 |

## 4. 비즈니스 규칙

- 정렬: 최근 등록순(createdAt DESC, 동시각은 id DESC tiebreaker).
- ⚠️ 관심 등록 후 상품이 삭제돼도 목록에는 그대로 노출(조인 필터 없음, 갭).

## 5. 필요한 데이터 후보

| 데이터 | 설명 |
| --- | --- |
| memberId | 토큰 principal |

## 6. 변경되는 데이터

| 데이터 | 변경 내용 |
| --- | --- |
| (없음) | 조회 전용 |

## 7. API 후보

| Method | URL | 설명 |
| --- | --- | --- |
| GET | /api/members/me/favorites | 내 관심목록 (인증) |

## 8. 테스트 관점

| 구분 | 테스트 내용 | 연계 |
| --- | --- | --- |
| 성공 | 최근 등록순 정렬 | FV-10, FV-32(R) |
| 성공(엣지) | 관심 없음 빈 리스트 / 삭제 상품 노출(갭) | FV-11, FV-12 |

# UC-022. 관심상품 취소

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 유즈케이스 ID | UC-022 |
| 유즈케이스명 | 관심상품 취소 |
| Actor | 일반회원 (USER) |
| 목적 | 본인 관심목록에서 상품을 제거한다 |
| 사전 조건 | 인증됨, 해당 관심이 등록되어 있음 |
| 성공 결과 | 관심 제거(하드 삭제) |
| 실패 결과 | 등록되지 않은 상품 취소 시 거부 |
| 우선순위 | Medium |
| 담당자 | 권건우 |

## 2. 기본 흐름

1. USER가 productId로 관심 취소를 요청한다.
2. 시스템이 (memberId, productId) 관심을 조회한다.
3. 관심을 삭제한다.
4. 성공 응답을 반환한다.

## 3. 예외 흐름

| 번호 | 예외 상황 | 시스템 처리 |
| --- | --- | --- |
| E-001 | 등록되지 않은 관심 취소 | 404 `FAVORITE_002 FAVORITE_NOT_FOUND` |

## 4. 비즈니스 규칙

- 관심 취소는 **하드 삭제**(다른 도메인의 soft delete와 다름).
- 본인 관심만 취소 가능((memberId, productId)로 조회).

## 5. 필요한 데이터 후보

| 데이터 | 설명 |
| --- | --- |
| memberId | 요청자 |
| productId | 대상 |

## 6. 변경되는 데이터

| 데이터 | 변경 내용 |
| --- | --- |
| favorites | row 물리 삭제 |

## 7. API 후보

| Method | URL | 설명 |
| --- | --- | --- |
| DELETE | /api/products/{productId}/favorites | 관심 취소 (인증) |

## 8. 테스트 관점

| 구분 | 테스트 내용 | 연계 |
| --- | --- | --- |
| 성공 | 등록된 관심 취소 | FV-20 |
| 실패 | 미등록 취소 | FV-21 |
