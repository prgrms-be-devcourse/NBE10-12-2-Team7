# UC-006. 상품 등록

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 유즈케이스 ID | UC-006 |
| 유즈케이스명 | 상품 등록 |
| Actor | 일반회원 (USER) |
| 목적 | 판매 상품을 등록한다 |
| 사전 조건 | 인증됨, 카테고리 존재 |
| 성공 결과 | 상품 생성(ON_SALE, viewCount=0, hidden=false) |
| 실패 결과 | 입력 검증 실패/회원·카테고리 없음 시 거부 |
| 우선순위 | High |
| 담당자 | 한상민 |

## 2. 기본 흐름

1. USER가 제목·설명·가격·지역·카테고리로 등록을 요청한다.
2. 시스템이 제목(공백 불가)·가격(0 이상) 필드를 검증한다.
3. 작성자(회원)를 조회한다.
4. 카테고리를 조회한다.
5. 상품을 생성·저장한다(tradeStatus=ON_SALE, viewCount=0, hidden=false).
6. 등록 결과를 반환한다(201).

## 3. 예외 흐름

| 번호 | 예외 상황 | 시스템 처리 |
| --- | --- | --- |
| E-001 | 제목 공백 | 400 `PRODUCT_005 INVALID_PRODUCT_TITLE` |
| E-002 | 가격 null 또는 음수 | 400 `PRODUCT_006 INVALID_PRODUCT_PRICE` |
| E-003 | 작성자 회원 없음 | 404 `MEMBER_NOT_FOUND` |
| E-004 | 카테고리 없음 | 404 `CATEGORY_001 CATEGORY_NOT_FOUND` |

## 4. 비즈니스 규칙

- **검증 순서**: 필드검증(제목·가격) → 회원 조회 → 카테고리 조회. (제목 공백+회원 없음이면 `INVALID_PRODUCT_TITLE`이 우선)
- 가격은 **0원 이상**(0 허용, 음수 불가).
- 신규 상품은 항상 ON_SALE·미숨김·조회수 0으로 시작.

## 5. 필요한 데이터 후보

| 데이터 | 설명 |
| --- | --- |
| memberId | 작성자 (토큰) |
| title | 제목 (필수, ≤100) |
| description | 설명 (≤1000) |
| price | 가격 (0 이상) |
| region | 거래 지역 |
| categoryId | 카테고리 FK |

## 6. 변경되는 데이터

## 7. API 후보

| Method | URL | 설명 |
| --- | --- | --- |
| POST | /api/products | 상품 등록 (인증) |

## 8. 테스트 관점

| 구분 | 테스트 내용 | 연계 |
| --- | --- | --- |

# UC-008. 상품 검색

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 유즈케이스 ID | UC-008 |
| 유즈케이스명 | 상품 검색 |
| Actor | 비회원 (Guest) |
| 목적 | 키워드·카테고리·가격범위·거래상태로 상품을 검색한다 |
| 사전 조건 | 없음 (공개) |
| 성공 결과 | 조건에 맞는(삭제·숨김 제외) 목록 |
| 실패 결과 | 잘못된 가격범위/거래상태 시 거부 |
| 우선순위 | High |
| 담당자 | 한상민 |

## 2. 기본 흐름

1. 사용자가 검색 조건(전부 선택)을 입력한다.
2. 시스템이 조건을 정규화한다(전부 null이면 빈 검색).
3. 가격 범위 유효성을 검증한다(음수 불가, min≤max).
4. 거래상태 문자열을 enum으로 파싱한다(null이면 무시).
5. Specification으로 미삭제·미숨김 + 조건 일치 상품을 id DESC로 조회한다.
6. 결과를 반환한다(200).

## 3. 예외 흐름

| 번호 | 예외 상황 | 시스템 처리 |
| --- | --- | --- |
| E-001 | minPrice<0 또는 maxPrice<0 | 400 `SEARCH_001 INVALID_SEARCH_CONDITION` |
| E-002 | minPrice>maxPrice | 400 `INVALID_SEARCH_CONDITION` |
| E-003 | tradeStatus 공백(non-null)/잘못된 값 | 400 `TRADE_001 INVALID_TRADE_STATUS` |

## 4. 비즈니스 규칙

- 키워드는 **제목 OR 설명** 부분일치, **대소문자 무시**(양쪽 lower).
- 가격 경계는 포함(min≤price≤max).
- 모든 조건은 AND 결합, null 조건은 무시.
- 검색 결과에도 삭제·숨김 상품은 제외.

## 5. 필요한 데이터 후보

| 데이터 | 설명 |
| --- | --- |
| keyword | 제목·설명 검색어 (옵션) |
| categoryId | 카테고리 필터 (옵션) |
| minPrice / maxPrice | 가격 범위 (옵션, 0 이상) |
| tradeStatus | 거래상태 enum 문자열 (옵션) |

## 6. 변경되는 데이터

| 데이터 | 변경 내용 |
| --- | --- |

# UC-010. 상품 수정

## 1. 개요

| 항목 | 내용 |

## 2. 기본 흐름

1. Owner가 변경할 거래상태를 입력해 요청한다.
2. 시스템이 거래상태 문자열을 enum으로 파싱한다.
3. 상품 조회 → 삭제 여부 → 작성자 일치를 검사한다.
4. 거래완료 상품 제약을 검사한다.
5. 현재와 다른 상태면 변경한다.
6. 결과를 반환한다(200).

## 3. 예외 흐름

| 번호 | 예외 상황 | 시스템 처리 |
| --- | --- | --- |
| E-001 | request null/공백/잘못된 거래상태 | 400 `INVALID_TRADE_STATUS` |
| E-002 | 상품 없음 | 404 `PRODUCT_NOT_FOUND` |
| E-003 | 삭제된 상품 | 404 `DELETED_PRODUCT` |
| E-004 | 타인의 상품 | 403 `PRODUCT_OWNER_ONLY` |
| E-005 | 거래완료 상품을 다른 상태로 변경 | 400 `TRADE_002 CANNOT_CHANGE_COMPLETED_PRODUCT` |

## 4. 비즈니스 규칙

- **검사 순서**: 상태파싱 → 없음 → 삭제 → 작성자 → 완료제약.
- 거래완료(COMPLETED) 상품은 **COMPLETED 유지만 허용**, 다른 상태로 되돌릴 수 없음.
- 현재 상태와 동일한 요청은 변경 없이 통과(no-op).
