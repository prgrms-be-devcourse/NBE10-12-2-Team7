# Admin 유즈케이스 (UC-026 ~ UC-038) — 담당: 팀장

공통 사전조건: `ROLE_ADMIN` 인증. **USER 접근 → 403, 비인증 → 401**. 상태변경 DTO는 `@Valid` 없이 서비스에서 `trim()` 후 `valueOf` 파싱(대소문자 구분).
⚠️ 알려진 갭(테스트 전략 §8): **N1**(관리자가 관리자 잠금 가능), **N3**(대시보드 pendingReports는 RECEIVED만), 집계에 삭제·숨김 포함.

조회/단순 CRUD 계열(UC-026·027·029·030·033·035·036)은 공통 패턴이라 간략화하고, 상태/숨김/삭제/대시보드는 상세화한다.

# UC-028. 회원 상태 변경

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 유즈케이스 ID | UC-028 |
| 유즈케이스명 | 회원 상태 변경 |
| Actor | 관리자 (ADMIN) |
| 목적 | 회원 상태를 ACTIVE/SUSPENDED/DELETED로 변경한다 |
| 사전 조건 | ADMIN 인증, 대상 회원 존재 |
| 성공 결과 | 상태 변경(DELETED면 deletedAt 기록, 그 외 deletedAt 클리어) |
| 실패 결과 | 회원 없음/잘못된 상태값 시 거부 |
| 우선순위 | High |
| 담당자 | 팀장 |

## 2. 기본 흐름

1. ADMIN이 대상 회원과 새 상태값을 입력해 요청한다.
2. 시스템이 대상 회원을 조회한다.
3. 상태값을 trim 후 enum으로 파싱한다.
4. 회원 상태를 변경한다(DELETED→deletedAt=now, 그 외→deletedAt=null).
5. 변경 결과를 반환한다(200).

## 3. 예외 흐름

| 번호 | 예외 상황 | 시스템 처리 |
| --- | --- | --- |
| E-001 | 대상 회원 없음 | 404 `MEMBER_NOT_FOUND` |
| E-002 | 상태값 null/공백 | 400 `ADMIN_002 INVALID_MEMBER_STATUS` |
| E-003 | 잘못된 상태 문자열(소문자 포함) | 400 `INVALID_MEMBER_STATUS` |
| E-004 (갭 N1) | 다른 관리자/본인 대상 변경 | **현재 허용**(가드 없음) — 운영 정책 결정 필요 |

## 4. 비즈니스 규칙

- 상태값은 앞뒤 공백 제거(`trim`) 후 파싱하되 **대소문자는 구분**("suspended"는 거부).
- DELETED로 변경 시 deletedAt 기록, ACTIVE/SUSPENDED로 변경 시 deletedAt 클리어(복구 가능).
- ⚠️ N1: 관리자가 다른 관리자·본인을 잠글 수 있음(가드 미구현).

## 5. 필요한 데이터 후보

| 데이터 | 설명 |
| --- | --- |
| memberId | 대상 회원 |
| status | 새 상태 문자열(ACTIVE/SUSPENDED/DELETED) |

## 6. 변경되는 데이터

| 데이터 | 변경 내용 |
| --- | --- |
| members.status | 새 상태 |
| members.deletedAt | DELETED면 now(), 그 외 null |

## 7. API 후보

| Method | URL | 설명 |
| --- | --- | --- |
| PATCH | /api/admin/members/{memberId}/status | 회원 상태 변경 (ADMIN) |

## 8. 테스트 관점

| 구분 | 테스트 내용 | 연계 |
| --- | --- | --- |
| 성공 | SUSPENDED/DELETED 변경, DELETED→ACTIVE 복구(deletedAt 클리어), 공백 trim | AD-04~AD-06, AD-10 |
| 실패 | 회원 없음, null/공백/잘못된 값 | AD-07~AD-09 |
| 실패(갭) | N1 관리자 잠금 현재 동작 고정 | AD-11 |
| 실패(인가) | USER 403 / 비인증 401 | AD-12, AD-13 |
