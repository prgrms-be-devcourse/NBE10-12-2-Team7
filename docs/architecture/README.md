# 시스템 아키텍처 — dongne-market

원칙: **한 문서 = 한 레벨 = 한 청중** ([C4 모델](https://c4model.com/) 기반).

> 한 장에 모든 걸 담지 않는다. 보는 사람과 목적에 따라 줌 레벨을 고른다.

현재는 단일 **Spring Boot 모놀리식 + MySQL** 구성이다. 자세한 구성은 [02-container.md](02-container.md) 참고.

## 작성·유지 규칙

- **도구**: [Mermaid](https://mermaid.js.org/) — GitHub가 마크다운에서 그대로 렌더한다. 별도 빌드·이미지 파일 없음.
  - 분기·구조 = `flowchart`, 시간순 상호작용 = `sequenceDiagram`, 데이터 = `erDiagram`.
- **docs-as-code**: 구조가 바뀌면 **같은 PR**에서 해당 다이어그램도 갱신한다. 코드와 문서가 함께 버전 관리된다.
- **레벨별 유지 주기**: 상위(L1·L2)는 거의 안 바뀐다 → 가끔 점검. 하위(L3·ERD)는 코드 변경에 민감 → 변경 시 갱신.
- **오너십**: 전체·공통 구조도는 팀장이, 도메인 상세는 각 도메인 담당이 유지한다.
- **프로즈 우선**: 토폴로지(구성) 질문이 아니면 글로 설명한다. 모든 것을 그림으로 만들지 않는다.

> 이전 `docs/logics/` 컨벤션(도메인 로직 흐름 문서)은 이 폴더로 통합되었다. 동작 흐름(시퀀스/플로우)도 해당 레벨 문서 안에서 함께 다룬다.
